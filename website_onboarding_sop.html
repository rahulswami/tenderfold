New Git Repository & Environment Setup

Sever old database links, isolate the repository, and generate a clean production environment file.

Whenever onboarding a new domain (e.g., tenderfold.in), create an independent Git repository to prevent accidental production overwrite of legacy clients.

Terminal — Git Remote & Env Initialization
# 1. Create and connect to new GitHub Repository git remote set-url origin https://github.com/rahulswami/[new_repo_name].git # 2. Copy and configure .env cp .env.example .env php artisan key:generate
Key Values to set in .env:
  • APP_NAME="[New Brand Name]"
  • APP_URL=https://[newdomain.in]
  • DB_DATABASE=[new_db_name]
  • DB_USERNAME=[new_db_user] & DB_PASSWORD=[password]
  • SESSION_DRIVER=file & CACHE_STORE=file (Ensures zero crash on initial setup)

Database Creation, Isolation & Zero-Bleed Reset

Purge old clinic/store data while retaining CMS schema, security roles, and admin accounts.

Execute the SQL cleanup script to truncate legacy operational data, chat histories, doctor listings, and old leads:

phpMyAdmin / MySQL Query — Zero-Bleed Reset
SET FOREIGN_KEY_CHECKS = 0; -- Purge Old Operational Data & Leads TRUNCATE TABLE `leads`; TRUNCATE TABLE `lead_activities`; TRUNCATE TABLE `form_submissions`; TRUNCATE TABLE `chat_rooms`; TRUNCATE TABLE `chat_messages`; TRUNCATE TABLE `admin_notifications`; TRUNCATE TABLE `web_notifications`; TRUNCATE TABLE `push_subscriptions`; -- Reset Admin User Credentials UPDATE `users` SET `email` = 'admin@[newdomain].in', `name` = '[Brand] Admin' WHERE `id` = 1; SET FOREIGN_KEY_CHECKS = 1;
Clean Database Verification Ready for New Seeding

Database schema is ready for seeding new service records, pricing lists, testimonials, and home slides.

HTML-to-Blade Conversion Engine

Transform raw HTML files into clean, dynamic, CMS-connected Blade templates.

  • Copy Assets: Move all template images, icons, CSS, and JS into public/assets/.
  • Extract Master Layout: Create resources/views/layouts/app.blade.php containing the common <head>, sticky Header, dynamic Services dropdown, #bookModal, and Footer.
  • Inject Blade Yields: Ensure @yield('title'), @yield('meta_description'), @yield('schema'), and @yield('content') are present in layouts/app.blade.php.
  • Bind Dynamic Placeholders:
    • Phone Number: {{ $site['phone'] }}
    • WhatsApp Link: https://wa.me/{{ $site['whatsapp_number'] }}
    • Dynamic Services Loop: @foreach($services as $service)
    • Dynamic Reviews: @foreach($testimonials as $test)
  • Form Action: Point contact & pickup forms to route('contact.submit') with @csrf.

Hostinger Live Deployment & Self-Healing

1-Click deployment procedure with automated resolution for 403 Forbidden and AppKey errors.

Follow these exact steps inside Hostinger hPanel to launch in under 2 minutes:

Step 1: Git Deploy

Connect Repository

In hPanel > Git, add repo URL and branch main. Click Deploy.

Step 2: MySQL DB

Import SQL Dump

Create database in hPanel and import database.sql via phpMyAdmin.

Step 3: Self-Heal

Run /deploy.php

Open https://[domain]/deploy.php in your browser for 1-click verification.

Common Live Server Errors & Instant Fixes

Error Message Root Cause Instant Fix
403 Forbidden Document root points to public_html instead of public_html/public. Root .htaccess is pre-configured in this repository to rewrite into public/ automatically.
MissingAppKeyException APP_KEY is blank in production .env. Opening /deploy.php auto-generates a secure 32-byte key and writes it directly to .env.
Database file ... does not exist .env has DB_CONNECTION=sqlite instead of mysql. Set DB_CONNECTION=mysql and update database name/user in .env.
